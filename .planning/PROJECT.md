# Project: Orchestra Runtime как агентный движок Operium Desktop

## Core value

Operium Desktop должен запускать локальные модели через Orchestra Runtime и
получать при этом надёжность уровня Ollama/LM Studio при работе агентов, а не
только чата: рантайм обязан оставаться отзывчивым во время генерации, не падать
от длинного контекста, стримить при включённых инструментах и не переплачивать
префиллом на каждом шаге агентного цикла.

## Problem

Рантайм функционально богат (два совместимых API, native tool-calling, vision,
structured output, адаптивная загрузка, изоляция в воркере), но в agentic-режиме
ведёт себя нестабильно. Измерения (см. `.planning/codebase/CONCERNS.md`)
показывают, что нестабильность — не про качество инференса, а про четыре вещи:

1. **Control plane блокируется исполнением.** Во время генерации `/api/tags`
   отвечает 9.3 c, `/api/models` и `/api/status` — тоже. Клиент опрашивает их с
   таймаутами 2–3 с, поэтому во время работы агента рантайм для клиента
   «мёртв».
2. **Стриминг исчезает при `tools`.** TTFB 8.03 c против 0.0004 c без
   инструментов. Агент всегда шлёт инструменты — значит, стриминга нет никогда.
3. **Длинный контекст ломает запрос.** Переполнение даёт HTTP 500 с сырой
   ошибкой llama.cpp, а проверка стоит после начала декодирования — то есть на
   границе возможен SIGSEGV, а он в дефолтном in-process режиме убивает сервер.
4. **Агентный цикл платит полный префилл на каждом ходу** — KV-кэш очищается
   на каждом запросе.

## Target users

- Operium Desktop (флагман): агенты с песочницей, плагинами и обёртками
  инструментов, много коротких шагов с tool-call'ами и длинной историей.
- Расширение Operium Orchestra для VS Code: автозапуск рантайма, UI со списком
  моделей и статусом.

## Scope

**Входит:** отзывчивость control plane, устойчивость к падениям и переполнению
контекста, агентный стриминг и протокол ответа, переиспользование KV-кэша,
параллелизм и мультимодельность, честный учёт памяти, наблюдаемость,
нагрузочный и chaos-харнесс в CI.

**Не входит:** собственный формат моделей, обучение/дообучение, распределённый
инференс, публикация моделей в реестр (`/api/push`), замена llama.cpp.

## Constraints

- Совместимость API не ломается: `/v1/*` (OpenAI) и `/api/*` (Ollama) остаются
  контрактом для существующих клиентов; новое добавляется как расширение.
- Целевое железо — Apple Silicon с unified memory (эталон: M4 Pro / 24 GB),
  плюс CUDA и CPU-сборки.
- llama.cpp остаётся сабмодулем; всё, что можно, решается на стороне Go, без
  форка upstream.
- Go 1.22, CGo, chi; текущая слоистость `handler → service → engine` сохраняется.

## Definition of done (milestone)

Агентная сессия Operium Desktop на локальной 20B-модели проходит 20 шагов с
инструментами так, что: клиент ни разу не потерял связь с рантаймом, ни один
шаг не оборвался ошибкой контекста, токены видны с первого шага, а второй и
последующие ходы не переплачивают полным префиллом.
