# VLM + agent context smoke verification — 2026-09-22

## Runtime defect reproduced and fixed

The installed host/worker and a fresh build from `14c8ec3` both failed real Qwen3.5 image requests with `number of media markers in text (0) does not match number of bitmaps (1)`.

Native chat rendering preserved `<__media__>` correctly. The failure was in `mtmd_bridge.cpp`: pinned llama.cpp `91c631b21` defines `mtmd_input_text` as `text, text_len, add_special, parse_special`, but the bridge still used the old three-field positional initializer. `add_special=true` became a one-byte text length. Named assignments now set byte length and both flags explicitly.

`TestNativeVisionCompletionIntegration` failed before the fix and passed afterwards: a generated red PNG is recognised in both buffered and streamed completion. `TestNativeVisionMarkerIntegration` separately checks the template boundary. Tests require explicit local model/projector environment variables; normal CI skips these multi-GB integration fixtures.

```sh
ORCHESTRA_TEST_VISION_MODEL_PATH=/path/model.gguf \
ORCHESTRA_TEST_VISION_MMPROJ_PATH=/path/mmproj.gguf \
go test ./internal/engine -run 'TestNativeVision.*Integration' -count=1
```
